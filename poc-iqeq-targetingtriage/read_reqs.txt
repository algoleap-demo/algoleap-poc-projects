1. Overview  
This document defines an Agentic AI Proof of Concept (POC) for a Targeting & Triage system. 
The system uses multiple specialised agents to deliver intelligent account prioritisation and 
sales enablement.  
 
The system is designed to:  
• Identify high -priority accounts  
• Evaluate upsell potential  
• Generate prioritised recommendations  
• Provide explainable reasoning  
• Highlight uncertainty and conflicts  
 
2. Objective  
Enable a goal -driven, multi -agent system that can autonomously support the sales process 
through intelligent data analysis, prioritisation, and decision support.

3. Agent Definitions  
The system is composed of six specialised agents, each with a defined responsibility and data 
contract. The agents collaborate in an orchestrated pipeline to deliver end -to-end account 
prioritisation.

6. Execution Flow  
The agents execute in the following sequence for each scoring request:  
 
1. Planner Agent receives and interprets the user request  
2. Data Agent retrieves and validates account data  
3. Scoring Agent computes ML -based propensity scores  
4. Reasoning Agent assigns priority bucket and generates rationale  
5. Validation Agent checks for ML vs LLM conflicts  
6. Formatting Agent prepares the structured output payload  
7. Response returned to the calling system or user

9. Decision Rules  
The following rules govern how ML and LLM outputs are combined:  
 
Section  Details  
ML Layer  • Provides statistical propensity score  
• Based on historical data patterns  
• Does not incorporate contextual signals  
LLM Layer  • Provides contextual, signal -based reasoning  
• Assigns priority bucket with human -readable rationale  
• Does not recalculate ML scores

10. Human -in-the-Loop  
The system must support human oversight and intervention at the output stage:  
 
• Review of agent -generated prioritisation before actioning  
• Manual override capability for priority bucket assignments  
• Feedback capture to support future model improvement  
• Conflict resolution guided by human judgment  
 
11. Constraints  
The following constraints are mandatory and must be enforced across all agents:  
 
Constraint  Description  
No ML recalculation in LLM  The Reasoning Agent must not recalculate or override ML scores  
No unsupported fields  Agents must not generate or expose fields not defined in the 
output schema  
Structured outputs only  All agent outputs must conform to the defined JSON schema  
Conflict visibility  Conflicts must always be surfaced — never silently suppressed  
 
12. Success Criteria  
The POC will be considered successful when all of  the following criteria are met:  
 
• End-to-end agent flow executes without errors for a representative dataset  
• Account prioritisation is meaningful and aligns with business expectations  
• Conflicts between ML and LLM outputs are visible in output payload  
• Output is explainable and auditable by sales teams  
• Human override and feedback mechanisms are functional
